# @votetorrent/web-data

Shared browser data layer for the authority dashboard (`apps/VoteTorrentDashboard`) and the
public no-login election view (`apps/VoteTorrentPublic`).

## Why there is no `"."` export (D-04)

The package's `exports` map has exactly two keys, `./public` and `./officer`, and **no bare
`"."`**. This is a structural, not a stylistic, choice: D-04's anonymity guarantee only holds if
a forbidden (officer-only) query is *unreachable* from the public entry point. A bare `.` export
would let a consumer import both audiences through a single specifier, collapsing that guarantee
from *structural* (a resolution error) to *decorative* (a review convention someone could violate
by accident). `packages/ui-web` has a `.` export because it has no audience split to protect;
this package does.

## Module placement rule

| Module | Location | Reachable from |
|---|---|---|
| `open-db.js`, `reattach.js`, `networks-registry.js` | `src/` (package root) | **both** barrels |
| `elections.js`, `ballots.js`, `registrations.js`, `capability-tables.js` | `src/officer/` | `./officer` only |
| (public reads, landing in a later plan) | `src/public/` | `./public` only |

The connection layer is audience-neutral: it opens a database and selects no application table.
D-04's split is about **which tables a consumer can query**, not about connection management.

## The `nmHoistingLimits: workspaces` duplicate-instance hazard

The repo's `.yarnrc.yml` sets `nmHoistingLimits: workspaces` — every workspace gets its own copy
of every declared dependency. A second copy of `@quereus/quereus` means a second `Database` class
identity and a second `@quereus/plugin-indexeddb` module registry, which fails plugin
registration or an `instanceof` boundary in a build that still exits 0 (the same signature spike
089 measured for React one stack up).

Mitigation: this package declares `@quereus/quereus`, `@quereus/plugin-indexeddb` and
`@votetorrent/vote-engine` in **both** `peerDependencies` and `devDependencies` (the proven
`ui-web` React shape), and **any app that imports this package must add `@quereus/quereus` and
`@quereus/plugin-indexeddb` to its own Vite config's `resolve.dedupe`.**

`apps/VoteTorrentDashboard/vite.config.ts` does this in the same plan that creates this package.
`apps/VoteTorrentPublic` declares the workspace dependency here but does not import it yet — it
inherits this same `resolve.dedupe` obligation at its first real import, planned for a later plan
in this phase (the public app's `ElectionShell.tsx` attaching the addressed network's IndexedDB
through `@votetorrent/web-data/public`). Do not defer adding the dedupe entries past that plan.

## Generated files

`src/officer/capability-tables.js` is generated by
`apps/VoteTorrentDashboard/scripts/generate-capabilities.mjs` from the same schema parse that
produces `apps/VoteTorrentDashboard/src/auth/capabilities.js`. **Do not hand-edit it.** Re-run
`yarn workspace votetorrent-dashboard capabilities:generate` after any change to `view Scope` or a
`.Scope = '<code>'` enforcement site in `packages/vote-core/schema/votetorrent.qsql`, then commit
the result. A drift between the two generated artifacts is caught by
`apps/VoteTorrentDashboard/test/node/capabilities.test.mjs`'s staleness check.
