Split the single-batch `db.exec()` call in `NetworksEngine.create()` (lines 99-194) into sequential `exec()` calls so that the `Admin` INSERT commits before the `Officer` INSERT runs. Quereus 3.2.1 evaluates `Officer.AdminValid` CHECK eagerly during each INSERT, not at batch end.

Split into three sequential `exec()` calls with the same parameter object:

1. First exec: User + UserKey + Authority + Admin (4 INSERTs) -- all have no cross-table forward dependency within this group
2. Second exec: Officer (1 INSERT) -- depends on Admin existing, so must run after first exec
3. Third exec: Network (1 INSERT) -- depends on Authority existing, already committed in first exec

Keep every context binding, parameter key, and interpolated `${tid}` value unchanged. Wrap each `exec()` call in the existing `try/catch` error handler block (same QuereusError/MisuseError rethrow pattern). The `catch` block at lines 195-203 becomes the outer try/catch wrapping all three sequential calls.

Apply the identical fix to `NetworkEngine.createAuthority()` (lines 54-119 in network-engine.ts). It has the same batch pattern with Authority, Admin, and Officer in one exec(). Split into:
1. First exec: Authority + Admin (2 INSERTs)
2. Second exec: Officer (1 INSERT)

Keep the same tid binding (currently hardcoded as `tid: 1`), same context bindings, same catch block shape.

  <action>
Fix two bugs in `ElectionsEngine.createElection()` (lines 105-150) and export a Tid peek function per D-04.

1. **Date format conversion (Pitfall 3):** Import `Temporal` from `temporal-polyfill` (already used in authority-engine.ts). Convert the three date fields before binding:
   - `date: Temporal.Instant.fromEpochMilliseconds(e.date).toString()`
   - `revisionDeadline: Temporal.Instant.fromEpochMilliseconds(e.revisionDeadline).toString()`
   - `ballotDeadline: Temporal.Instant.fromEpochMilliseconds(e.ballotDeadline).toString()`
   This produces ISO 8601 strings ending in `Z` that pass the `isISODatetime` regex in initialize.ts and satisfy the `DateValid` CHECK constraint.

2. **Signing nonce parameter (Pitfall 2):** Extend `createElection` signature to accept an optional second parameter:
   `async createElection(election: ElectionInit, options?: { signingNonce?: string }): Promise<void>`
   Change the bind value from `signingNonce: null` to `signingNonce: options?.signingNonce ?? null`.
   The `IElectionsEngine` interface in vote-core does NOT change (the options param is optional so callers without it still compile). Verify this by checking vote-core's `IElectionsEngine.createElection` signature accepts the existing single-arg form.

3. **Tid peek export (Research Q1):** Add a module-level exported function below the `let nextTid = 1` declaration:
   `export function peekNextElectionTid(): number { return nextTid }`
   This is test-only infrastructure. The seed helper calls `peekNextElectionTid()` to read the Tid that the NEXT `createElection()` call will use, then seeds `AdminSigning.Digest` with that exact Tid so the `Election.InsertValid` CHECK passes.

4. **Apply the same date fix to `adjustElection()`** (lines 45-92): convert `e.date`, `e.revisionDeadline`, `e.ballotDeadline` using `Temporal.Instant.fromEpochMilliseconds(...).toString()` to maintain consistency.
