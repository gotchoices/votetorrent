## Engine Gap (the reason for re-skip)

`UserEngine.create` (`packages/vote-engine/src/user/user-engine.ts:122`) emits this SQL:

```sql
insert into User (Id, Name, ImageRef)
with context SigningNonce = null, InviteSlotCid = null, InviteSignature = null, Tid = ${tid}
values (:userId, :userName, :userImageRef);
```

The `InviteSlotCid` and `InviteSignature` context columns are hardcoded to `null`. `User.InsertValid` (`packages/vote-core/schema/votetorrent.qsql:465-474`) reads:

```sql
constraint InsertValid check on insert (
    -- First user in the network - no invite, no signing
    (context.SigningNonce is null and context.InviteSlotCid is null and context.InviteSignature is null
        and (select count(*) from User) = 1)
        -- or Valid Invite for this user
        or (context.SigningNonce is null and context.InviteSlotCid is not null and context.InviteSignature is not null
            and exists (
                select 1 from InviteSlot I where I.Cid = context.InviteSlotCid and I.InviteSignature = context.InviteSignature
            )
        )
)
```

Because `createTestNetwork` already inserts the first user as part of network bootstrap, the second insert's `(select count(*) from User) = 1` branch is no longer reachable — and the invite-bound branch requires non-null context columns that the engine refuses to pass. **No test-side workaround exists** unless the test bypasses the engine entirely (raw SQL with the right context), which violates "REAL ENGINE" semantics.

Confirmed failure mode (the 3 tests, run unskipped):

```
Error: Quereus error (code 19): CHECK constraint failed: InsertValid
  at UserEngine.rethrow (.../src/user/user-engine.ts:249:19)
  at UserEngine.create (.../src/user/user-engine.ts:116:18)
  at async Context.<anonymous> (.../test/user.spec.ts:705:9)
```

The plan explicitly says: *"If the engine's `create` method does not yet accept invite context params, document the gap in the SUMMARY — do not modify the engine in this plan (that would require a follow-up)."* — so 12.3-07 commits only the test-side seed wiring.

### Follow-up plan needed

Extend `UserEngine.create` to accept an optional `{ inviteSlotCid, inviteSignature }` second argument, mirroring `NetworkEngine.createAuthority`'s Plan 12.2-01 Part B extension. The engine SQL would change from the hardcoded-null `with context` clause to bind-parameter columns:

```sql
with context SigningNonce = null,
             InviteSlotCid = :inviteSlotCid,
             InviteSignature = :inviteSignature,
             Tid = ${tid}
```

When the overload is shipped, **the only change required in this file is `it.skip(` → `it(` on three lines** — the seed half, the `auth.ctx` thread-through, and the builder call are all already in place. The annotation explicitly cites `UserEngine.create lacks invite-context overload` so the discoverability of this follow-up is unambiguous.

## Decisions Made

- **Re-skip rather than retro-fit raw SQL.** The plan's must_haves.truths #2 says "calling the user-creation engine method." A raw-SQL bypass would satisfy the unskip-count letter but break the REAL ENGINE semantic. Re-skipping with the seed-half wired is the precise observed-failure documentation the plan calls for (action step 4: "If the engine's `create` method does not yet accept invite context params, document the gap in the SUMMARY").
- **Per-test seed composition (not beforeEach).** Keeps each `it.skip` self-contained so the follow-up patch is a 3-line diff (3× `it.skip` → `it`), not a refactor.
- **Import the layered helpers, do not retire `createUserEngineForExistingNetwork`.** That helper is still used by 7 other tests in the file (UserEngine.getSummary, addKey, revise, revokeKey REAL ENGINE tests) which already work under the existing engine SQL because they don't insert a User row.
- **`seedUserInvite` officer-scope assumption is correct for this consumer.** The `User.InsertValid` invite-bound branch checks only `InviteSlot.Cid + InviteSlot.InviteSignature`, not the InviteType. Officer-scope is fine.
