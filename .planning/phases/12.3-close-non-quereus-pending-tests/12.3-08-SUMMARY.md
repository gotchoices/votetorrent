# Phase 12.3 Plan 08: Group F — elections.spec.ts addQuestion/addOption Ballot Seeding — Summary

## What Built

### `elections.spec.ts:441` — `addQuestion` INSERTs a ProposedQuestion row

**Before (skip annotation):** "BLOCKED: NOT NULL constraint on ProposedQuestion.DependsOn (ElectionEngine.addQuestion does not bind DependsOn column)"

**After (test body):** Full `createTestNetwork → addTestAuthority → addTestElection → seedBallot(elec, 'ballot-1')` chain before invoking `new ElectionEngine(...).addQuestion(ballotId, q)`. Authority/election ids resolved off the real fixtures (`auth.authority.id`, `'election-1'` per `makeElectionInit` default) instead of the prior hardcoded `'authority-1'`.

**After (skip annotation):** "BLOCKED: quereus 3.2.1 raises NOT NULL on ProposedQuestion.DependsOn despite `text null` schema (Ballot-row blocker is now resolved by seedBallot; this is the remaining upstream issue)."

Diagnosis recorded in-source (multi-line comment above the test) explains:
- The prior annotation was directionally wrong about the cause but accidentally correct that NOT NULL still fires.
- Schema line 707 of `votetorrent.qsql` declares `DependsOn text null`.
- The engine DOES bind `:dependsOn` (line 430 of `election-engine.ts`: `dependsOn: question.dependsOn ? JSON.stringify(question.dependsOn) : null`) — it is not an engine-side missing binding.
- The failure surface is quereus' parser / parameter-binding pipeline not honoring `text null` for this column. Same `text null` pattern works elsewhere (e.g., `Authority.ImageRef` — `network-engine.ts:92` binds the same JS-null shape successfully), suggesting either a column-specific or context-specific edge case.

### `elections.spec.ts:469` — `addOption` INSERTs a ProposedOption row

**Before (skip annotation):** "BLOCKED: NOT NULL constraint on ProposedOption.Details (ElectionEngine.addOption does not bind Details column)"

**After (test body):** Same full seeding chain as the addQuestion test, plus a `engine.addQuestion(ballotId, q)` call to insert a `ProposedQuestion` row matching `'q1'` (so the subsequent `addOption(ballotId, 'q1', o, 0)` invocation has a referenced question code in the ProposedQuestion table). The ProposedQuestion insert fails on the upstream blocker described above, but the test body shape is correct for once that's resolved AND once a `seedQuestion` helper is added.

**After (skip annotation):** "BLOCKED: ProposedOption.QuestionCodeValid requires a canonical Question row; needs a seedQuestion fixture helper (mirror of seedBallot) which does not yet exist."

Diagnosis recorded in-source explains:
- ProposedOption.BallotIdValid (line 781 of `votetorrent.qsql`) is satisfied by seedBallot.
- ProposedOption.QuestionCodeValid (line 782) is `exists (select 1 from Question Q where Q.BallotId = new.BallotId and Q.Code = new.QuestionCode)` — it checks the canonical **Question** table, NOT ProposedQuestion. The schema comment "references ProposedQuestion.Code" on `ProposedOption.QuestionCode` is misleading vs. the actual CHECK.
- `Question.MutationValid` (line 674 of `votetorrent.qsql`) requires a full AdminSignature pipeline with scope='ceb' and a 12-tuple Digest formula — i.e. a `seedQuestion` helper analogous to the existing `seedBallot`. ElectionEngine.addQuestion only writes ProposedQuestion, so the engine cannot stand in for the helper.

## Decisions Made

### Re-skip rather than force-pass

Plan 12.3-08's `<action>` step 6 explicitly authorized this outcome: *"If a test fails for a NEW residual blocker after seeding the Ballot row, re-skip with a precise annotation — do not regress to the obsolete DependsOn/Details claim."*

Both tests fall under that clause: the planner expected `seedBallot` to be the only remaining blocker, but unskip attempts surfaced two distinct new blockers (one upstream-quereus, one fixture-shaped) that are out of this plan's surface (test-rewrite only; no engine changes, no new fixture helpers, no quereus patches).

### Out-of-scope follow-ups (NOT done here)

1. **A `seedQuestion(elec, ballotId, question)` fixture helper** would unblock the `addOption` test. It would mirror `seedBallot`'s pattern: an `insert into AdminSigning` with `Scope = 'ceb'` and the 12-tuple Digest from `Question.MutationValid`, `SigningEngine.sign(...)`, then a raw `insert into Question` under the signed nonce. This is structurally identical to `seedBallot` but with a wider Digest signature. It should be scoped to a separate fixture-helper plan if/when more tests need canonical Question seeding.
2. **Quereus null-binding investigation for `text null` columns** — needs a minimal reproducer (a single `text null` column where `:param = null` raises NOT NULL despite the schema). Goes through the quereus upstream tracker, not this codebase.

### Authority id sourcing

Switched the `new ElectionEngine(...)` config from the prior hardcoded `'authority-1'` to `auth.authority.id`. `makeTestNetworkInit` does not pin a specific authority id (`NetworksEngine.create` generates it), so the prior hardcode was wrong-but-unobservable when the test was skipped. The new shape is correct under the seedBallot chain.
